Olist 订单与配送分析

从订单、支付与评价的多表关系出发，构建可信指标，识别配送问题，并用执行计划验证 SQL 优化。

延迟订单的低评分比例更高

主分析窗口：2017-01 至 2018-08；低评分为 1–2 分，分母为有评价的有效配送订单。

这是关联证据。建议排查运输环节与预计交付承诺，再设计改善措施的验证方案。

错误 JOIN 会改变销售额

2018 年 1 月，订单明细直接关联支付和评价。

将各个明细表先聚合到订单粒度，再进行关联；所有金额与源表对账。

主要商品品类

主分析窗口内已交付商品 GMV，不含运费；货币 BRL。

配送排查优先区域

至少 100 个有效配送订单；同时看比例与受影响订单数量。

使用 customer_unique_id 识别复购客户；每个订单只选最新一条评价；预计配送日期按日历日比较。

卖家排查限定单卖家订单。未评价订单保留；未知配送状态不计入延迟率分母。
